A command-conditioned latent world model, trained on a CNC machine with 17 sensors, selected and locked on that machine alone, then evaluated once on a machine it has never seen, which measures only 10 of them.

Three questions, three answers. Lower RMSE is better; all numbers are in z units of the source normalizer.

Abstract

Industrial world models must move between machines whose dynamics, sensing interfaces and command conventions differ. This study asks whether a command-conditioned latent world model—trained to predict future representations of the process rather than to reconstruct future samples—keeps its value on a machine it has never seen: a source CNC machine exposes 17 sensor channels, the target sharing 10 of those. All model selection uses source data only, and the locked configuration is evaluated on the target once. Two findings follow. First, latent-predictive pretraining brings no in-domain forecasting gain over matched training from scratch, so source accuracy alone cannot show what such a representation is worth. Second, the transferred model beats persistence on the unseen machine (with R² ≈ 0.01 against the target mean) but trails official forecasters that normalize each input window by its own statistics; a post-lock ablation, declared before it ran, shows that this input normalization alone closes the gap, and closing it costs predictive calibration. Cross-machine transfer under partial sensor overlap is therefore a distinct evaluation axis for command-conditioned world models.

02Two machines, one set of weights

The same process runs on two machines that do not measure the same things. Under domain shift the channels are the same but the signals differ; under schema shift the list of channels itself changes. The target machine has both.

An absent channel is not a zero. Each channel is one token with a presence bit; tokens marked absent are dropped before attention and pooling, so the seven source-only channels simply do not exist for the model on the target, and the same weights read both machines without imputation or retraining.

03The world model

A forecaster answers “what happens next”. A world model answers “what happens next if the controller issues these commands”. The commands are an input given in advance; nothing here is closed loop.

What is modelled, and how it is trained

Object

pθ(xt+1:t+H∣xt−K+1:t,mt−K+1:t,at−K+1:t+H)

Future sensor rows given the last K = 32 rows, their presence mask m and the commands a, past and planned. This is the object of interest, not the training loss.

Model

pθ(xt+ℋ∣·)=∏h∈ℋ𝒩(xt+h;μψ(z^t+h),diagσψ2(z^t+h)) z^t+ℋ=gφ(ztc,(a¯h)h∈ℋ) ztc=fθe(xt−K+1:t,mt−K+1:t,at−K+1:t)

A Gaussian head ψ on each predicted latent, over the grid ℋ = {1, 2, 4, 8, 16} s, with θ = (θe, φ, ψ). The future commands enter through their means āh = mean(at+1:t+h), nested over the five horizons.

Loss

ℒSSL=ℒlat+0.05ℒVICReg+0.10ℒschema+0.05ℒact
  • ℒlat smooth-L1 between each predicted latent and the stop-gradient EMA target latent, averaged over horizons.
  • ℒVICReg variance hinge and covariance penalty (α = 25, β = 1), no invariance term; only the context half carries gradient.
  • ℒschema the prediction from a further random channel subset (κ = 0.65) is pulled toward the detached prediction of the fuller view; with a whole-window channel dropout of 0.15, a channel is missing from the reduced view with probability ≈ 0.45, close to the 7/17 ≈ 0.41 the target lacks.
  • ℒact a small head rω regresses the mean command āh from the context latent and the target latent: a weak, multi-step inverse-dynamics term.

λlat = 1 is a normalization: in pretraining, a common rescaling of the four weights is absorbed by AdamW (up to its ε and the gradient clip), so three weights are free. Fine-tuning then adds the Gaussian negative log-likelihood of the head.

Read the equations carefully

  • The self-supervised loss is a surrogate for the object, not a bound on its likelihood: during pretraining the head receives no gradient. Whether it helps is an empirical question, and on the source machine it does not (Q1).
  • The model is a product of per-horizon marginals: horizons and channels are treated as conditionally independent given the context and commands, so it does not model their correlations.
  • All horizons come from one pass with a causal slot mask; no predicted latent is fed back, so there is no autoregressive rollout, and the future commands enter only as nested means, not as a step-by-step profile.

04Selection without looking at the target

Twenty candidates were written down before any ran and ranked on source validation only. The target machine enters no decision before the lock.

The composite score weights clean, schema-drop, masked and long-horizon RMSE, calibration and the SSL validation loss, each z-scored within the pool, and penalizes collapsed seeds and weak command use (RMSE with shuffled commands less than 1.02 times RMSE with true ones). When the provisional winner changed under confirmation, locking was refused and seeds were added. Two candidates collapsed: the plain JEPA control without anti-collapse regularization on all four seeds, and the largest model (d = 512, eight layers) on three of four.

05Results on the unseen machine

Same 2,457 target windows, same 10 shared channels, no target-side selection for any method.

  1. RevIN gains most on the channels whose level shifts across machines (Z-axis current RMSE 0.84 → 0.20). It costs calibration because a stationary context window (spindle stopped, constant power) shrinks the instance scale to √ε ≈ 3 × 10−3; the variance is de-normalized with that scale, so a start-up within the horizon costs hundreds of nats. The mean is de-normalized with the same scale, so RMSE is protected.
  2. The target windows have been read by the pre-lock model (several diagnostic reads, outside selection), once by the locked model, and once by the declared RevIN ablation. No further target evaluation of this pipeline can be called sealed.
  3. On the source machine ordinary supervised models are stronger (RSSM 0.759, MLP 0.771, locked candidate 0.822 on source validation). The claim is transfer under partial sensor overlap, not source forecasting.

06Adaptation and scope

A few target windows help, on the pre-lock model. That curve is a diagnostic, not a confirmatory result.

What the numbers support today

  • One transfer pair. One source machine, one target machine, seven independent target runs. Broader invariance claims wait for more machines.
  • One locked checkpoint, evaluated once. The target number is a single seed; run-level confidence intervals and the few-shot curve on the locked model are still to compute.
  • The latent objective is not isolated on the target. Every arm, scratch included, trains with the latent terms, so no target arm measures their contribution.
  • Predictive, not decision-theoretic. No policy, no planning, no closed loop: the commands are inputs, and downstream control is future work.

Protocol and compute

Source sessions split 42 / 11 / 9 (group-disjoint), with zero window overlap. A unit audit corrected three cross-machine mismatches before modelling: power W→kW, commanded feeds mm/s→mm/min (×60) and spindle deg/s→rpm (÷6). All experiments ran on one NVIDIA DGX Spark (single GB10 GPU), about six GPU-days in total.
